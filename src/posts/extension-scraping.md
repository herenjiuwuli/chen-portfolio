# 浏览器扩展抓数踩坑：循环引用、异步渲染与数据一致性

> 一句话理解：给 MCN 数据工具写的浏览器扩展要在 5 个平台网页上捕获互动数据，一路踩了循环引用坏对象、SPA 异步渲染、并发请求「张冠李戴」等坑——这些教训对任何「解析网页数据」的活都通用。

> 说明：涉及平台细节已脱敏（下文用「某短视频平台」等指代），聚焦可复用的技术经验。

## 我之前的误解

- 以为「页面全局变量」就是数据源——直接读 `window.xxx` 就行，结果一堆循环引用对象，`JSON.stringify` 直接抛错。
- 以为「拦截到接口」就等于「拿到当前页面的数据」——结果并发请求把推荐流数据覆盖了正确数据。
- 以为「代码没取到 = 字段名猜错」——实际上有时候是**平台网页版根本不提供**这个数据。

## 坑 1：循环引用「坏对象」≠ 数据源

- 现象：读页面全局变量，`JSON.stringify` 抛错（循环引用），拿不到数据。
- 实际原因：某短视频平台把真实数据放在 `<script id="...">` 标签里（URL 编码），而同名全局变量是个带循环引用的坏对象，根本不能 stringify。
- 解法：从 `document.getElementById(...)` 取文本 → 解码 → `JSON.parse()`。
- **教训**：遇到循环引用对象要换数据源（找 SSR 内嵌标签 / 接口），别硬 stringify。

## 坑 2：SPA 数据根本不在初始 HTML 里

- 现象：解了标签、JSON 也 parse 出来了，但按各种字段路径找，数据全是空。
- 实际原因：页面加载后数据是 SPA **异步 fetch 详情接口**拿回来的，只存内存，初始 HTML 里只有页面配置。而且接口返回的是 `snake_case`，之前按 `camelCase` 探测全 false，进一步坐实「猜字段名」方向就错了。
- 解法：拦截 fetch/XHR，从详情接口响应里取。
- **教训**：先验证「数据到底在不在这个位置」，再谈怎么取；字段名从接口响应实测，别写死猜测。

## 坑 3：content script 只在页面加载那一刻注入

- 现象：加了注入钩子后没生效。
- 实际原因：扩展刷新后，**已打开的旧标签页不会自动补注入**，必须手动刷新页面。
- 解法：改扩展后两步走——① 扩展管理页刷新扩展 → ② F5 刷新目标页。
- **教训**：对「注入时机」的理解要完整，调试时先确认目标页是不是旧加载。

## 坑 4：并发请求，钩子「张冠李戴」

- 现象：捕获到 6 万赞，页面明明显示 3 千，标题也不是当前视频的。
- 实际原因：页面**并发**请求「当前视频详情」+「推荐流列表」，钩子对每个响应无脑取「第一个视频对象」，推荐流把正确数据覆盖了。
- 解法：按视频 id 精准匹配——只拦截请求 URL 里 `id=` 等于当前视频的请求，取对象也只取 id 匹配的，取不到就丢弃（**宁可空，不误抓**）。
- **教训**：拦截/抓取时要做「身份校验」，默认「拿到一个就是对的」是 bug 温床。

## 坑 5：CSS 模块化 hash class 让固定选择器失效

- 现象：某社交平台数据全在 DOM，但用固定 class 名永远匹配不到。
- 实际原因：新版组件库的 class **带 hash 后缀**（如 `_num_198pe_46`），固定 class 永远匹配不上；旧版属性已废弃。
- 解法：用部分匹配 `[class*="_num_"]`，或语义定位（图标 title、按钮文案往上找同容器数字）。
- **教训**：框架/CSS 模块化场景要用「部分匹配」或「语义定位」，别写死完整 class。

## 坑 6：区分「代码没取到」和「平台根本没提供」

- 现象：某平台视频页，赞能取到但评论/收藏/分享全空，试遍所有路径。
- 实际原因：部分数据在 GraphQL 异步接口（不在初始状态里）；**收藏数、分享数网页版根本不提供**（App 有、网页没有）。
- 解法：异步接口单独拦截；平台不提供的数据留空手动填。
- **教训**：平台网页端功能裁剪很常见——先确认数据「是否存在」，再排查「怎么取」。

## 可复用的经验总结（清单）

1. 循环引用对象 → 换数据源（SSR 标签 / 接口），别硬 stringify
2. SPA 数据 → 拦截 fetch/XHR；字段名从响应实测
3. 改扩展 → 扩展管理页刷新 + 目标页 F5，两步缺一不可
4. 并发请求 → 按 id 精确匹配，宁可空不误抓
5. hash class → 部分匹配 / 语义定位
6. 取不到 → 先区分「代码问题」还是「平台不提供」
