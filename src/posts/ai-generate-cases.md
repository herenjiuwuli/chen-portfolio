# 给 API 测试平台加「AI 生成用例」：输入接口，AI 自动出 8 条测试用例

> 一句话理解：在自研的 API 测试平台上加一个 AI 模块——输入接口信息，DeepSeek 自动设计覆盖正常/边界/异常的测试用例，人工验收后入库执行。测试平台从「人写用例」变成「人写 + AI 写」双模式。

## 背景

我做的 API 自动化测试平台（Fastify + SQLite + Vue3）已经有完整的用例管理、执行、JSONPath 断言、定时任务。但有个问题：**写用例还是靠人**——每测一个接口，要手动想「正常情况、边界、异常」再一条条填。

既然平台里已经接了 AI 能力（后来加的），不如让 AI 也来写用例：输入一个接口的 method/url/body，它按测试思维设计 5-8 条用例，我验收后一键入库。

## 过程

### 后端：加一个生成接口

```js
// POST /api/ai/generate-cases
输入：{ method, url, headers?, body?, description? }
行为：构造 system prompt（你是资深 API 测试工程师…覆盖正常/边界/异常）→ 调 DeepSeek
输出：{ cases: [{ name, method, url, expected: { status, jsonChecks } }] }
```

关键点：**AI 输出的用例模型必须完全对齐平台已有的用例结构**（name/method/url/expected），这样生成结果能直接复用现有的创建用例接口，不用额外转换。

### 前端：预览 + 勾选 + 批量保存

用例列表页加「AI 生成用例」按钮 → 弹窗填接口信息 → 生成后以表格预览（每条可勾选、可编辑、可删）→ 「保存选中」批量入库。**AI 是助手，人验收后数据才进库。**

## 踩坑（最值钱的部分）

### 坑 1：AI 长输出被截断 → JSON 解析失败
第一次测试，返回「AI 返回内容不是合法 JSON」。查了半天发现：**没设 `max_tokens`**，DeepSeek 输出 8 条长用例时被截断，JSON 不完整。
修：请求体加 `max_tokens: 8192`。

### 坑 2：AI 用代码表达式表示超长输入
某条用例的 body 出现 `"username": "a".repeat(1000)`——这不是合法 JSON！AI 想表达「超长输入」时用了 JS 表达式。
修：prompt 加约束——「禁止使用 .repeat() 等代码表达式；表示超长输入直接写 20-30 个实际字符，重点是测边界行为」。

### 坑 3（环境）：后端不读 .env
写好的 .env 里有 key，但代码加载不到（`DEEPSEEK_API_KEY not configured`）——项目没装 dotenv。
修：`npm i dotenv` + `import 'dotenv/config'`。

## 结果

- 真实调用生成 8 条用例：正常登录（200 + JSON 断言）、缺参（400）、超长（400）、错误密码（401）——正常/边界/异常全覆盖
- 51 个 Vitest 回归全绿（老功能没改坏）
- 平台从「人写用例」升级成「人写 + AI 写」双模式

## 收获

1. 让 AI 干活的关键不是「会调 API」，而是**把输出模型钉死 + 给足约束**（不然它会自由发挥出 .repeat() 这种非法 JSON）
2. 测试 AI 输出要用「给边界输入」的思维：超长输出（max_tokens）、非法表达（.repeat()）都是边界情况——我给自己写的测试思维，正好用在测 AI 上
3. 环境类坑（dotenv）会吞时间，遇到「代码明明对但跑不起来」，先查环境加载
